# Руководство по исходным изображениям для «Номерок» / Numbi

Этот документ задаёт единый стандарт для будущей партии примерно из 300
изображений. Цель исходника — не самостоятельная иллюстрация, а чистая основа,
которая после уменьшения до целевой сетки 24–90 клеток остаётся узнаваемой и превращается в
приятную раскраску по пикселям.

## Canvas

- Рекомендуемый исходный размер: 1024×1024 px.
- Допустимы 768–2048 px по длинной стороне; больше не добавляет полезных деталей
  для сетки максимум 90×90.
- Предпочтительное соотношение сторон — 1:1. Для естественно широких объектов
  допустимы 4:3 и 3:2; importer сохраняет пропорции внутри прямоугольной сетки.
- Форматы: PNG, JPEG или WebP. PNG с прозрачностью — самый предсказуемый вариант.
- Один файл не должен содержать рамку, подпись, UI, mockup или несколько вариантов.

## Background

- Лучший фон — полностью прозрачный.
- Второй вариант — ровный белый или почти белый фон без текстуры и теней до края.
- Не использовать интерьер, пейзаж, узор, шум, бумажную фактуру или градиентный фон,
  если фон не является намеренной частью самой раскраски.
- Белый фон importer удаляет только flood-fill от краёв. Если главный объект белый
  и соединяется с краем, нужен прозрачный PNG либо `removeWhiteBackground: false`.
- Не имитировать прозрачность шахматной сеткой.

## Composition

- Один главный generic-объект, одна понятная поза и один визуальный центр.
- Силуэт должен распознаваться без внутренних деталей и без названия файла.
- Объект занимает ориентировочно 65–80% ширины и высоты usable canvas.
- Допустимы 1–3 крупных второстепенных элемента, только если они поддерживают
  основной сюжет и не дробят картинку на мелкий шум.
- Не создавать коллажи, толпу персонажей, сложную перспективу или множество
  перекрывающихся предметов.

## Margins

- Оставлять вокруг объекта примерно 10–15% чистого поля с каждой стороны.
- Уши, хвост, колёса, крыша, листья и другие узнаваемые части не должны обрезаться.
- Не прижимать объект к краю: после crop и padding ему нужен минимум один свободный
  пиксель вокруг силуэта.
- Центрировать объект визуально, а не только математически; тяжёлая деталь не должна
  создавать ощущение, что картинка падает к краю.

## Detail level

- Проектировать изображение под целевой этап: 1–10 = 24×24; 11–25 = 30×30;
  26–50 = 45×45; 51–75 = 65×65; 76–100 = 75×75; 101+ = 90×90.
  На поздних этапах добавлять различимые детали и оттенки, а не увеличивать ранний пиксельный результат.
- Использовать крупные формы толщиной не менее 2–3 будущих пикселей.
- Удалять микродетали: отдельные ресницы, шерсть, чешую, тонкие спицы, мелкие
  украшения, складки, крошечные пальцы и точечные узоры.
- Лицо — только из нескольких крупных, разнесённых элементов. Мелкие лица и
  реалистичные черты после pixelization дают случайные точки.
- Контур не обязан быть чёрным; важнее ясная граница между крупными зонами.
- Если важная часть исчезает при preview 64×64 px, она слишком мелкая.

## Color

- Предпочтительно 5–9 визуально различимых цветовых зон; максимум игры — 12.
- Каждая зона должна занимать несколько соседних пикселей, а не одну точку.
- Использовать заметно разные hue/lightness. Два почти одинаковых бежевых или
  зелёных оттенка не должны становиться разными игровыми номерами.
- Избегать огромной одноцветной заливки: один цвет желательно держать ниже 70–75%
  playable pixels.
- Белые детали допустимы на прозрачном или контрастном фоне.
- Не использовать неоновые края, chromatic aberration или полупрозрачные блики.

## Lighting

- Свет ровный, мягкий и иллюстративный.
- Одна простая светлая зона и одна простая тёмная зона допустимы, если обе крупные.
- Не использовать сложные блики, отражения, subsurface scattering, rim light,
  киношный контровой свет или множество источников света.
- Градиенты свести к минимуму: quantization превращает их в полосы и лишние номера.

## Shadows

- Допустима одна простая компактная тень как крупная цветовая форма.
- Не использовать фотореалистичные мягкие тени, ambient occlusion по всему контуру,
  длинные сложные тени или зернистые полутени.
- Тень не должна соединять объект с белым краем и мешать удалению фона.

## Text

Текст запрещён: никакого названия, букв, цифр, логотипов, вывесок, водяных знаков,
подписей или речи. После уменьшения он не читается и создаёт плохие одиночные
пиксели. Игровые номера добавляются самим runtime.

## Copyright

- Использовать оригинальные generic subjects: кот, ракета, дом, велосипед, фрукт,
  цветок, сказочный замок без узнаваемой франшизы.
- Не копировать известных защищённых персонажей, бренды, логотипы, фирменную одежду,
  кадры фильмов, чужие иллюстрации или узнаваемый character design.
- Для каждого source должна быть понятна лицензия/история создания и право на
  коммерческое использование в Яндекс Играх.

## Example good prompt

```text
Оригинальная дружелюбная иллюстрация рыжей лисы для детской пиксельной раскраски,
одна лиса сидит целиком по центру, чёткий узнаваемый силуэт, крупные простые формы,
7 хорошо различимых плоских цветов, минимум внутренних деталей, мягкое ровное
освещение без градиентов, прозрачный фон, свободное поле 12% со всех сторон,
без текста, логотипов, водяных знаков и известных персонажей, квадрат 1024×1024.
```

Для широкого предмета в prompt явно указать `полный объект, ничего не обрезано,
соотношение 4:3`; соответствующие `columns/rows` затем задать в `import.json`.

## Example bad prompt

```text
Фотореалистичная лиса в густом лесу на закате, очень детальный мех, листья и трава,
сильное боке, сложные тени и отражения, маленькие светящиеся частицы, надпись FOX,
логотип в углу, крупный план с обрезанными ушами.
```

Такой source даёт шумный фон, сотни случайных оттенков, одиночные пиксели,
неразличимые номера и слабый силуэт.

## Batch preflight

Перед генерацией всей партии проверить 10–20 разных сюжетов в реальном workflow:

```text
source.* + import.json
→ npm run import:images
→ npm run qa:levels
→ проверка qa/catalog.html
→ npm run validate:levels
```

В QA отклонять или перерабатывать картинки, если силуэт не узнаётся, объект касается
края, playable area слишком мала/велика, один цвет доминирует, соседние номера почти
неразличимы либо появилось много изолированных клеток. Только после согласования
этого стандарта масштабировать генерацию до 300 source-файлов.
