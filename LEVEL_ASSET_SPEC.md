# Спецификация пиксельного уровня «Номерок» / Numbi

Это полный контракт ассетов игры. Основной способ добавления контента — дать игре
обычную PNG, JPEG или WebP-картинку: build-time импортёр сам превращает её в
пронумерованную пиксельную раскраску.

## 1. Что получается в игре

- Рисунок состоит только из одинаковых квадратных клеток.
- Каждая незакрашенная клетка показывает номер нужного цвета.
- У каждого будущего цвета свой нейтральный серый оттенок.
- Tap окрашивает одну клетку, drag — сразу подходящие пиксели под указателем; неправильный цвет не меняет прогресс.
- Палитра всегда строится из реальных цветов конкретной картинки.

## 2. Рекомендуемый входной материал

Лучший результат даёт один хорошо различимый объект:

- PNG с прозрачным фоном — идеальный вариант;
- JPEG/WebP/PNG на чистом белом фоне тоже поддерживается;
- объект должен занимать большую часть кадра и не касаться краёв;
- предпочтительны чёткий силуэт, умеренное число деталей и контрастные цвета;
- текст, водяные знаки, тонкие линии и сложный фотографический фон лучше убрать.

Белый фон удаляется flood-fill только от границ. Поэтому белый глаз, блик или другая
замкнутая белая деталь внутри объекта сохраняется. Для белого объекта на белом фоне
нужен прозрачный PNG либо `removeWhiteBackground: false`.

## 3. Папка входной картинки

```text
content/imports/
  011-fox/
    source.png
    import.json
```

Имя изображения должно быть `source.png`, `source.jpg`, `source.jpeg` или
`source.webp`. В папке должен быть ровно один такой файл.

Обязательный стандарт композиции и готовые промпты для генерации 300 исходников находятся в `SOURCE_IMAGE_GUIDE.md`.

## 4. Формат import.json

```json
{
  "id": "fox",
  "order": 11,
  "title": {
    "ru": "Лисёнок",
    "en": "Little Fox"
  },
  "category": "animals",
  "tags": {
    "ru": ["лиса", "лисёнок", "животное"],
    "en": ["fox", "animal", "cute"]
  }
}
```

Общие `schemaVersion`, `contentVersion` и grid-параметры находятся в
`content/imports/defaults.json`. Конкретный `import.json` может частично
переопределить `grid`. Строгая схема находится в `content/import.schema.json`.

## 5. Настройки пикселизации

- `columns`, `rows`: от 12 до 90. Preset определяется стабильным `order`.
- `colorCount`: от 1 до 12; обычно хорошо работают 6–9.
- `padding`: пустая рамка в клетках, от 0 до 6; стандартно 1.
- `removeWhiteBackground`: убирать связанный с краями белый фон; стандартно `true`.
- `whiteThreshold`: что считать почти белым, 200–255; стандартно 245.
- `alphaThreshold`: минимальная непрозрачность клетки, 1–255; стандартно 72.
- `mergeColorDistance`: RGB-distance для слияния почти одинаковых игровых цветов,
  0–100; стандартно 28.

Presets: 1–10 — 24×24; 11–25 — 30×30; 26–50 — 45×45; 51–75 — 65×65;
76–100 — 75×75; 101+ — 90×90. В defaults.json включено `progressiveGrid: true`.
Локальный `import.json.grid` переопределяет значения. Палитра растёт от 7 до 12 цветов.

Импортёр учитывает EXIF-ориентацию, обрезает пустое поле, вписывает объект с
сохранением пропорций и детерминированно группирует близкие RGB-цвета. Одинаковый
исходник и настройки всегда дают одинаковый уровень.

## 6. Запуск пакетного импорта

```bash
npm run import:images
npm run qa:levels
npm run build
```

Скрипт обрабатывает все подпапки `content/imports/` последовательно, чтобы партия
из сотен больших изображений не заполняла память. Ошибка одного source не скрывает
остальные: итог содержит imported, skipped unchanged, failed и warnings с ID/папкой.

Существующие уровни по умолчанию не перезаписываются. Намеренное обновление:

```bash
npm run import:images -- --force
```

Используйте `--force` только после проверки изменённого исходника. При reimport
сохраняются ручные title, tags, category и order; geometry/palette/difficulty
пересчитываются. Реальное изменение geometry или palette автоматически повышает
`contentVersion`, чтобы прежнее сохранение не раскрасило другую клетку.

Importer выдаёт неблокирующие warnings для слишком пустой/заполненной сетки,
доминирующего цвета, изолированных пикселей, похожих цветов и слишком простой
картинки. Их нужно просмотреть в `qa/catalog.html`.

## 7. Production-структура

Импортёр создаёт:

```text
content/levels/
  011-fox/
    level.json
    artwork.svg
```

Runtime никогда не читает `content/imports/`. Единственный production-источник —
`level.json + artwork.svg`. React-компоненты, routes и массив imports для нового
уровня не добавляются.

## 8. Постоянные ID и порядок

- `schemaVersion` равен 1.
- `id` — уникальный стабильный slug из строчных латинских букв, цифр и дефисов.
- `order` — уникальное положительное целое число.
- После публикации `id` нельзя менять: он является ключом прогресса.
- ID клетки вычисляется из координат, например `p-r04-c08`.
- Bitset-index не зависит от DOM: `index = row * 30 + column` с нулевыми
  координатами, а build всегда сортирует пиксели по row, затем column.
- `contentVersion` — положительное целое. Оно меняется при несовместимой geometry;
  runtime тогда безопасно начинает этот уровень заново.

## 9. Категории

Допустимы только:

- `animals`;
- `nature`;
- `food`;
- `houses-cities`;
- `space`;
- `transport`;
- `underwater`;
- `fantasy`;
- `landscapes`;
- `cute-objects`.

RU/EN-названия категорий уже находятся в i18n приложения.

## 10. Сложность

Сложность 1–5 автоматически определяется комбинированным score:
`max(columns, rows) * .65 + sqrt(playablePixels) * .3 + colorCount * .4`.
Границы: 26, 39, 59, 72. `import.json.difficulty` позволяет ручной override.
Допускается 60–8100 клеток. Difficulty, gridSize, regionCount и colorCount входят в manifest.

## 11. Палитра

- От 1 до 12 цветов.
- ID цвета — уникальное положительное целое число.
- Значение — непрозрачный HEX вида `#RRGGBB`.
- Каждый цвет обязан использоваться хотя бы одной клеткой.
- Цвет в `level.json`, а не `fill` SVG, является источником истины.
- Незакрашенный серый оттенок вычисляется runtime отдельно для каждого ID цвета.

## 12. Точный SVG-контракт

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 20 20">
  <g id="regions">
    <path
      data-region-id="p-r04-c08"
      data-color-id="3"
      data-label-x="7.5"
      data-label-y="3.5"
      d="M 7 3 H 8 V 4 H 7 Z"
    />
  </g>
</svg>
```

Каждый игровой path — ровно одна осевая клетка 1×1 с целыми X/Y. Центр номера обязан
быть точно `x + 0.5, y + 0.5`. Клетки не могут повторяться, перекрываться или
выходить за `viewBox`. `viewBox` начинается с `0 0`, имеет целые размеры от
8 до 30. Внутри находится одна группа `<g id="regions">`.

Не допускаются `transform`, `text`, `script`, `image`, `foreignObject`,
обработчики событий, внешние URL и незамкнутые/non-pixel path. Контуры, номера,
серые состояния, итоговые цвета и UI рисует приложение.

`data-legacy-region-id` существует только у десяти мигрированных стартовых уровней,
чтобы старое сохранение крупной области могло раскрыться в соответствующие клетки.
Новые уровни этот атрибут не используют.

## 13. Ручной уровень

Если исходник уже является готовой пиксельной схемой, можно скопировать
`content/templates/example-level/` прямо в `content/levels/` и изменить metadata
и клетки вручную. Шаблон содержит 62 клетки и три цвета. После правок обязательно:

```bash
npm run validate:levels
npm run build
```

## 14. Что проверяет валидатор

- наличие обоих файлов и корректный JSON;
- только разрешённые metadata-поля;
- schema version, ID, order, RU/EN title и tags;
- категорию, сложность и палитру;
- уникальные ID/order уровней и ID клеток;
- точный pixel path 1×1, целочисленную сетку и отсутствие наложений;
- центр номера и попадание всей клетки в viewBox;
- существующий color ID и использование каждого цвета;
- отсутствие исполняемого или внешнего SVG-контента.

Ошибка содержит имя папки и конкретную причину. Исправлять нужно source в
`content/levels/`, а не `public/generated/`.

## 15. Сгенерированные файлы

`npm run build:levels` инкрементально поддерживает:

```text
public/generated/
  levels-manifest.json
  levels/<id>.json
  thumbnails/<id>.webp
```

Manifest содержит только metadata и URL. Геометрия каждой раскраски лежит в своём
JSON и загружается только при открытии уровня. Цветные WebP-превью 320×320 создаются
через `sharp`; worker pool ограничен четырьмя задачами. Хэш
`level.json + artwork.svg` хранится в `.cache/`, неизменённые JSON/WebP пропускаются,
а `npm run build:levels -- --force` выполняет полную регенерацию.

## 16. Масштаб 300+ уровней

Для партии из 300 картинок создаются 300 входных подпапок, выполняется один
`npm run import:images`, затем `npm run qa:levels` и один `npm run build`. Каталог автоматически
подхватывает все уровни. Его progressive rendering показывает карточки партиями,
превью загружаются лениво, а геометрия закрытых уровней не попадает в память.

Перед релизом:

```bash
npm run test
npm run validate:levels
npm run catalog:fixture
npm run qa:levels
npm run build:yandex
```

`qa/`, `.cache/`, исходные `source.*`, `content/imports/`, tests и `node_modules`
являются development-only и проверяются как запрещённые элементы Yandex ZIP.
